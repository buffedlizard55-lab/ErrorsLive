Methods & data audit

Reproducibility is the product. python3 tools/run_all.py rebuilds every artifact from the raw feed archives in data/raw/ — and every feed archive was verified against the league's own linescore endpoint before it was admitted. This page is the audit trail.

1 · Sampling design (self-weighting by construction)

Stratum (team errors)Pool gamesSampledSampling fractionRaking weight

Pool = 222 MLB regular-season games on 15 audited dates (June–September 2026), extracted from official linescore endpoints only — every game in the sample is verifiable from the league's own scorekeeping feed. The design is error-ENRICHED (by intent: boring games are cheap to score, error games are the specimen) and is not self-weighting: any pool-representative rate must apply the raking weights above — validated by reconstructing the pool's mean 1.113 team-errors/game from this sample as 1.258 (sampling noise at n=24). Model objects fit P(class | batted-ball features) within play, which is far less distorted than the game-level error rate; the reported 1.91% base rate is the sample rate, labeled as such on the model page.

2 · Verification pipeline per feed archive

Each live-feed JSON (gamePk 822xxx–824xxx) was fetched in platform chunks, joined with byte-exact no-whitespace rules, json.loads-validated, and its final score cross-checked against the league pool manifest (222 games). Games that landed ON the chunk seam were healed at play boundaries, and every heal and every dropped character is logged forever in data/raw/{pk}.integrity.txt:

Rule: never guess or invent characters. Where a seam could not be deterministically healed, the game was re-fetched whole; where a heal dropped a play, the play-level coverage loss is in the integrity file, and the missing-play count (if any) is printed in data_quality.json's coverage section.

3 · Dataset build

bip.csv

One row per batted ball in play with a Statcast hitData object: gamePk, date, play/batter/pitcher ids, event type (hit/error/FC/out label), exit velocity, launch angle, distance, trajectory, hardness, RBI on play, half/score state, review flag. 1,271 rows / 1,868 plays across 24 games.

Label honesty

25 plays carry official eventType field_error; one (8/24 vs NYM, J. McNeil reach-on-error-aborted-strikeout) returned incomplete hitData, so the modeling set holds 24 labeled errors / 1,258 rows → 1.91% base rate. Errors charged within other eventTypes (throwing errors on a hit) are not labeled error → observed rate is a lower bound, printed on the model page.

games.csv

24 games: date, park, both teams' R/H/E from the verified pool manifest — the stratum audit readers can join back to the 222-game pool.

data_quality.json

Machine-readable audit: totals, missing-numeric vectors (12), multi-hitData anomalies (0), 'other' class rows (1), per-team error coverage vs. pool (lower bound 24/25, explained), and re-verified final scores for all 24 games.

4 · Modeling

sklearn 1.9 dataframe-free pipeline — StandardScaler + multinomial logistic (5 features + 8 indicators) for P{hit, error, FC, out} and a parallel binary logistic for P(error). Validation: 5-fold stratified OOF (seed 20260929), AUC 0.64 [0.52–0.75], Brier 0.019, 1,000× bootstrap CIs; isotonic-on-OOF recalibration reported, not smuggled into metrics. Empirical trajectory × EV-band surface (Wilson 95% CIs) is published next to every model curve — if the model ever disagrees with the surface in a data-dense bucket, the surface wins the argument.

5 · NYDN replay archive normalization

9 published CSVs (2014–2018 regular + postseason where the repo published them) with 4 real-world schema faults fixed deterministically in tools/build_nydn.py: mis-quoted game cells, comma-split player names (12 lost rows, logged), an extra "Record Keeping" status added to the vocabulary (not dropped), and source typos (e.g. 2014-04-31, 1;21 timestamp) kept verbatim and flagged in data/nydn_quality.json. 6,168 rows → 2,984 overturned → 227 run-affected by the printed heuristic.
