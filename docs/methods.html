Methods & audit

Every number on this site is produced by code in this repository from data fetched from official MLB endpoints. Nothing is typed by hand, and the audit suite recomputes the published figures on every push — including the ones that make the model look bad.

The pipeline

1 · Ingest (needs network → runs in CI)

tools/ingest_official.py walks /api/v1/schedule day by day, fetches each game's feed/live with a trimmed fields list, and re-checks every game's final score against /api/v1/game/{pk}/linescore. A mismatch is recorded, never repaired.

Why CI: the build sandbox this project is developed in has no route to statsapi.mlb.com. Rather than let anyone type numbers in, the fetch runs on a GitHub-hosted runner (.github/workflows/ingest.yml) and commits its derived CSVs back to the branch. The committed file data/ingest/ingest_report.json is the run's own report.

2 · Rebuild (offline, byte-reproducible)

python3 tools/run_all.py rebuilds the committed site artifacts from the committed sources: the 24-game audit sample (docs/data/bip.csv, games.csv), the model (model.json), the NYDN archive (overturned_calls.csv) and the live fixture board (live_sample.json). CI runs it and fails the build if git diff is not empty — i.e. if the committed artifacts are not exactly what the code produces.

python3 tests/test_pipeline.py then recomputes the published numbers again, independently, from the raw data.

Labels, and what is never invented

  • A play's label is the official scorer's own result.eventType from the feed. Nothing is inferred, imputed or hand-edited.
  • Batted balls with no complete Statcast vector are quarantined, not filled in: the count is published in data/data_quality.json and in the model's honesty block.
  • Two independent run-removal tests are published for reviewed plays: a hard consistency test (runners recorded at the plate vs the scoreboard delta) and a labelled heuristic (an overturned home-run/tag/force review whose corrected text takes a run off). The rule string is stored on every row that fires, and the counts are printed even when they are zero.
  • MLB's two-letter reviewType codes (MJ, MA, …) are stored verbatim and never translated by guesswork. Where a human-readable subject is needed the site uses the feed's own play text — e.g. “Marlins challenged (tag play), call on the field was overturned: …”.
  • Archived 2014–18 video short-links are resolved and the result recorded (status code and final URL) instead of being presented as working links.

Validation design

  • GroupKFold by game is the published cross-validation. Random folds are shown beside it as the optimistic bound, and the gap between them is published.
  • Group bootstrap (whole games resampled) gives the intervals, because games — not plays — are the independent unit here.
  • Model-free surface (trajectory × exit-velocity error rates with Wilson intervals) is published so the key relationship can be checked without trusting any model.
  • Calibration is published bin by bin, together with an isotonic re-calibration check.
  • The audit suite re-derives the model from the dataset the model declares it used, so a stale page fails CI instead of quietly misleading a reader.

Known limitations (kept current, not buried)

  • The model sees contact physics and pre-pitch context only. Fielder positioning, hang time, park, weather, the identity of the fielder and the scorer's own standards are not inputs — which is why P(error) tops out in the low single digits.
  • Out of fold, the model does not find errors: it ranks balls within a game and rules errors out. That is stated on the home page and in the honesty block of model.json, not only here.
  • Official review data in modern feeds mixes replay reviews with automated pitch-result challenges; both are kept, labelled with is_pitch_challenge, and counted separately.
  • Raw feeds are not committed for the ingested window (they are hundreds of megabytes). What is committed is the derived CSVs plus data/ingest/games.csv, which carries the exact official URL for every game so any row can be re-verified by anyone with network access.
  • Video: the per-play watch link is Baseball Savant's own player page for the league's playId. Direct .mp4 renditions are attached only when the official content endpoint exposes one for that exact play id.
