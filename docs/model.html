The model, and the evidence for it

Everything on this page is recomputed from docs/data/model.json, fitted by tools/train_model.py from the committed batted-ball CSV. It fits three independent heads: a binary error probability for SCORE/100, a four-class macro distribution, and an 11-category distribution for represented outcomes such as hits, errors, fielder's choices, outs, sacrifice flies and sacrifice bunts. The four-class error probability can differ from SCORE/100 because it comes from another fitted head. None estimates whether an initial scorer call will later be changed. The audit suite re-derives the metrics on every push.

Scope: this is a late-season 2026, single-season model. The reported cross-validation holds out games from the same collected window; it is not a test on future seasons, unseen scorers or a complete season.

How it is validated

Grouped cross-validation (the headline)

Folds are split by game, not by play. Each fold's StandardScaler is fitted on that fold's training games only. A stratified random-fold score is shown as a comparator; it is not assumed to be an upper or lower bound. The signed random-minus-grouped difference is published (–).

Uncertainty

Intervals come from a 1,000-draw group bootstrap (whole games resampled with replacement), so the interval reflects how much the estimate would move with a different set of games — the honest source of variance here, not the number of plays.

High-score review queue — grouped out-of-fold results

If the score is used to prioritize a limited number of plays, this table shows the observed error precision and recall among the highest-scored fraction of held-out games. The baseline precision is the model window's error rate. These are retrospective same-window results, not a promise about future seasons.

What a review actually costs — the queue table

The operational question is not “what is the AUC”, it is “how many plays must someone watch to catch how many errors”. These are grouped out-of-fold numbers for the shipped logistic model; the same table is in data/model.json as honesty.review_queue_oof, so a reader never has to trust a number typed into this page.

Feature experiments — what was tried and what did not work

A model page that only shows the winner hides the search. Everything below was fitted on the same folds and is reported even where it lost.

What the fitted model leans on — game-level permutation importance

Each feature is shuffled across whole games and the grouped out-of-fold AUC is recomputed. A large drop means the fitted model uses that column heavily; a drop at or below zero means shuffling it changed nothing measurable. This measures reliance, not causation — and it is the honest answer to “which input is doing the work”.

Calibration — do predicted probabilities track observed rates?

The raw calibration table is grouped out-of-fold. A nested GroupKFold isotonic Brier score is also reported: inner-fold predictions fit each calibrator, and the outer held-out games evaluate it. Correlations and mutual information
