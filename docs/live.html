Live board — the model on the official feed, ball by ball

When MLB's Stats API permits cross-origin reads, this page fetches today's schedule and game feeds directly in your browser, then re-polls live games every two minutes. If browser access is blocked, it falls back to the last committed snapshot produced by GitHub Actions. Refreshes are best-effort, not a real-time guarantee.

What SCORE/100 means. It is 100 × P(the final feed label is “error”), using contact physics and pre-pitch context. The model is not trained to predict whether an initial scorer call will later be changed. It never nominates “error” as its most likely class in grouped out-of-fold evaluation; use the score to prioritize review, not as a verdict. The official scorer's feed label remains the record of the play.

Watching for a decision? The alert console polls the same endpoints and tells you what changed between polls — a ruling appearing, a ruling changing (error → hit or fielder's choice), an RBI field moving, a review being overturned — with sound, optional browser notifications and an exportable ledger.

“No call in feed yet” means Statcast hitData is present but the current feed has no result.eventType. MLB does not publish an open-decision queue, so this feed state does not prove a scorer has a decision pending. RBI notes are conditional reminders under Rule 9.04, not automatic counterfactual rulings.

Run it yourself

python3 tools/fetch_live.py                        # today's slate (US Eastern game date)
python3 tools/fetch_live.py --date 2026-09-28      # a specific date
python3 tools/fetch_live.py --pk 823441            # one game, live, mid-inning
python3 tools/fetch_live.py --out docs/data/live_slate.json --csv-out docs/data/live_slate.csv

The browser path reads only public MLB endpoints. Local collection needs outbound HTTPS to statsapi.mlb.com; the page shows the last committed snapshot if direct access is unavailable.
