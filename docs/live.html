Live scoring feed — what might this play be scored as?

The page reads today's official MLB schedule and game feeds in your browser, then refreshes live games about every 30 seconds. It keeps observed official-scorer pending rulings, their final feed result when captured, and batted-ball model scores together. If browser access is blocked, it shows the latest committed snapshot. Polling and scheduled refreshes are best-effort, not real-time guarantees.

Three distinct model outputs — do not read them as one verdict. SCORE/100 is 100 × the binary model's estimated probability that the final captured macro-class is error. A separate four-class macro head reports a normalized hit / error / fielder's choice / out distribution; its error probability is independently fitted and can differ from SCORE/100. A third, 11-category model adds outcomes such as single, double, triple, home run, field out, force out, double play, sac fly and sac bunt. Its raw softmax probabilities are not post-calibrated. All three estimate final feed categories; none predicts whether an initial scorer call will later be changed. Grouped held-out top-1 accuracy for the detailed model is — in the same-season dataset. Use these as estimates, not official rulings; the official feed remains the record.
Official scorer pending is not guessed from missing data. The pending badge is shown only for exact MLB StatsAPI event-type registry values os_ruling_pending_primary or os_ruling_pending_prior, or the registry description Official Scorer Ruling Pending at verified event/result fields. A contact play with no result.eventType but no such marker is shown separately as “no event type in this capture”; it does not prove a scorer decision is pending. Official event-type registry ↗

Want the whole slate? The live scoreboard shows every game for any date with its scoring watch, and the all-games scoring feed streams each batted ball's 11-outcome distribution — this table remains the full per-row view of one date's plays.
Watching for a decision? The alert console polls the same endpoints and tells you what changed between polls — a ruling appearing, a ruling changing (error → hit or fielder's choice), an RBI field moving, a review being overturned — with sound, optional browser notifications and an exportable ledger.

A complete Statcast vector is required for a model score. When it is absent or incomplete, the row stays visible but the page prints no score. The four-class /100 model is limited to its training classes; the detailed model covers only the 11 event categories listed on Model & validation. RBI notes are conditional reminders under Rule 9.04, never automatic counterfactual rulings.

Pending rows are retained in this browser's local log. “Resolved” requires a later, component-specific event type: result.eventType for a primary plate-appearance marker, or a non-pending playEvents[].details.eventType on the same identified event for a prior base-running marker. A cleared marker by itself is not a resolution. Feed reclassifications are labelled as changes between observations; the public feed does not identify who made the change or why.

Run it yourself

python3 tools/fetch_live.py                        # today's slate (US Eastern game date)
python3 tools/fetch_live.py --date 2026-09-28      # a specific date
python3 tools/fetch_live.py --pk 823441            # one game, live, mid-inning
python3 tools/fetch_live.py --out docs/data/live_slate.json --csv-out docs/data/live_slate.csv

The browser path reads only public MLB endpoints. Local collection needs outbound HTTPS to statsapi.mlb.com; the page shows the last committed snapshot if direct access is unavailable.
