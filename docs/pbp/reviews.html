How to read it. This feed watches exactly two things: ⏳ official-scorer pending rulings (hit / error / fielder's choice not yet decided) and ✏️ scoring errors — plays the official feed currently rules an error, plus rulings observed to change between polls. Every row gets one number: the model's HIT score — its probability that this batted ball ends up scored a hit. On an error row a low score means the model reads a genuine error; a high score flags a play a scorer might rescind. It is a research estimate from Statcast shape, not the probability that a ruling changes. When a pending ruling lands, the row shows whether the model's pre-ruling lean matched.

Pending rulings are the exact registry marker os_ruling_pending_primary (plate appearance) / os_ruling_pending_prior (base running) from GET /api/v1/eventTypes; scoring changes are observed by snapshotting every completed play's official result.eventType and diffing it against previous polls — the feed carries no change marker, so a change is only ever a difference between two observations. A pending ruling decides how the play is charged and never removes a run from the score. Row times are when this browser first observed the play — the payload carries no per-play timestamp. The HIT score comes from the committed model in this repository (11-outcome head, hit = single + double + triple + home run); it is a research estimate with unresolved validation audits, not an official decision or a forecast of a ruling. Verdicts (✓/✗) compare only scores captured before the ruling landed. Everything else the old replay feed tracked (ABS, manager challenges, umpire reviews, boundary calls) remains on the full feed and per-game pages. Unofficial fan project; live data via the public MLB StatsAPI (statsapi.mlb.com). Not affiliated with MLB or MLB Advanced Media.
