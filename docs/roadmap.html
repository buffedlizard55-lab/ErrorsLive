What this session changed (three implementation and review passes)

  • The collection runs at season scale, in CI. tools/ingest_official.py walks the official schedule for the whole 2026 season window (regular season + postseason game types only), re-fetches each listed game, compares the feed score with the league linescore, and publishes docs/data/bip_official.csv (30,298 batted balls in the selected model window), docs/data/replays.csv (11,528 reviewed plays), a full game ledger and a report with its flags. The model uses the 590-game 2026-08-15–09-27 window (30,206 complete rows), not the 24-game enriched audit set. The full collector window has 2,430 games; 2,429 verified and game 823490 remains explicitly unverified.
  • Per-play video links are available for the current candidate set. The collector maps official play ids to Baseball Savant pages and attaches direct MP4 renditions when returned by the official video sources. The current 17 run-impact candidates have watch/download links. Older archive links are resolved when available and dead or unknown statuses are retained rather than hidden.
  • Feed changes are observable; an internal pending queue is not. tools/watch_rulings.py records `hitData` with no result.eventType and compares later captures. A changed field proves only that two observations differ; it does not establish that a scorer decision was pending, the decision time, or why the API changed. The before/after fields, official feed URL, and first-observation state are retained for manual review.
  • The live board is wired end to end. tools/fetch_live.py publishes today's slate; the page renders it, tries the official endpoint directly from the browser, and labels the committed fallback when that is blocked. The same numbers come out of tools/live_score.py, and the audit suite asserts the browser and CLI implementations agree to 1e-9 on every batted ball of the dataset.
  • The audit suite now recomputes what it claims. Section C refits the published model from the dataset the model itself names; section D checks the two scorer implementations; section H checks the field-level contracts between each page and the JSON it loads. A hand-typed number cannot survive.

Known limitations (read these before trusting anything)

  • The model is a ranking aid, not an error caller. With a 0.798% error rate, grouped out-of-fold top-1 accuracy is 74.71% but error recall is 0.000 — the arg-max is never "error". Grouped ROC AUC is 0.7808 (95% CI 0.7542–0.8056), while average precision is 0.02652 against the 0.00798 prevalence baseline. Top-10% risk ranking found 77 of 241 held-out errors (31.95% recall); use it to sort plays for a second look, never to make a ruling.
  • 24 games is still the hand-checkable audit set, and it is error-enriched — its 1.91% rate is not a population rate and is never quoted as one. It exists to keep a small, fully verified ledger beside the large sample.
  • The published error rate is the observed target-label rate. The model class is derived from result.eventType == field_error, not every kind of defensive misplay that may appear alongside another scoring classification. Post-game feed revisions can only be noticed if a scheduled capture observes the before/after values.
  • Run impact remains unconfirmed. The legacy runner-movement/score comparison is only a data- consistency diagnostic (zero discrepancies in this window), not proof of a removed run. Seventeen rows are heuristic candidates based on review/result text and type; all remain candidates requiring official-feed and video review.
  • Archive-to-feed joins are incomplete. The probe report shows one sampled 2014 feed with no reviewed plays/review types and one sampled 2017 feed with a review record; this does not establish coverage across every game or season. Archive rows without a validated join keep their original link/search fallback. Joining and checking the remaining historical rows is still backlog work.
  • No fielder positioning, hang time, or sprint speed is in the model. The sampled official feeds exposed no hit-coordinate keys in the probe report. Two 98 mph grounders can differ by where the fielders stood; do not treat the score's training-fit range as a theoretical ceiling.
  • Context is partly modelled, not fully. Base state, outs, inning and batter/pitcher handedness are in; score differential and leverage index are not.
  • The refresh is scheduled, not streaming. The probe report records wildcard CORS for one MLB schedule request, but the live game-feed endpoint must also be tested from a browser origin. The browser attempts direct access and falls back to the last committed snapshot; GitHub schedules are best-effort.
