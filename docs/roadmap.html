Known limitations (read these before trusting anything)

  • The model cannot find errors; it can only rank them. With a 0.80% error rate, out-of-fold top-1 accuracy is 74.7% but error recall is 0.000 — the arg-max is never "error". AUC is 0.781 (95% CI 0.754–0.806, grouped by game). Use it to sort balls for a second look, never to call one.
  • 24 games is still the hand-checkable audit set, and it is error-enriched — its 1.91% rate is not a population rate and is never quoted as one. It exists to keep a small, fully verified ledger beside the large sample.
  • The error label is a lower bound. A throwing error on a play scored a single is not an field_error event, so the true error rate is somewhat higher than the published one, and post-game scorer revisions only appear through tools/watch_rulings.py from the day they land.
  • Run removal remains a labelled heuristic for the archive. The league publishes the corrected call, not the pre-review scoreboard. The one rule that would be proof — runner movements versus scoreboard delta — never fires on the ingested window (published as zero with the explanation). Modern rows are flagged by an explicit textual rule and every flagged row carries the video needed to check it by eye.
  • 2014 archive rows cannot be machine-joined to a play id. The league's own feeds for 2014 carry no reviewDetails (probe report, 2026-09-29), so those rows keep their original short link plus a Film Room search. 2015–2018 do carry review metadata and play ids.
  • No fielder positioning, hang time, or sprint speed is in the model, and the feed exposes no hit coordinates. Two 98 mph grounders differ by where the fielders stood; that is why P(error) tops out near 9/100 rather than spanning the dial.
  • Context is partly modelled, not fully. Base state, outs, inning and batter/pitcher handedness are in; score differential and leverage index are not.
  • The refresh is scheduled, not streaming. CI collects on a schedule and the browser attempts the official endpoint directly; a true push ticker would need a hosted proxy or a data licence.
