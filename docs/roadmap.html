Known limitations (don't read past these)

  • 24 labelled errors is a very thin positive class. The AUC confidence interval [0.518, 0.748] includes coin-flip. Out-of-fold the model names the correct ruling on 72.8% of plays overall, but that is carried almost entirely by “out” (87.9% recall) and “hit” (50.5%); on error it scores 0/24 and on fielder's choice 0/10. The score is a ranking aid, not a classifier. Growing the sample is fix #1.
  • The error label is a lower bound. Errors charged inside other event types (a throwing error on a play scored a single) are not labelled field_error, so the observed rate understates the true one. Post-game scorer revisions never appear in the live feed at all.
  • No fielder positioning, hang time, or fielder identity. Two 98 mph grounders are different plays when one is at a shifted shortstop. These are outside the five Statcast inputs, which is precisely why the error probability tops out near 6/100 instead of spanning 0–100.
  • The pool's per-game error column was not re-verified this pass. Re-deriving 247 team errors needs 222 individual linescore calls. See Methods §2.
  • The run-removal flag on the replay archive is a heuristic, printed verbatim in the UI. A true ledger needs a box-score diff before and after each challenge.
  • Replay video links decayed at source. The 2014–2018 short links point at a video platform MLB has since replaced. Nothing is re-hosted; every row keeps its original link plus a Film Room search. Some 2014–15 clips are likely unrecoverable.
  • The live feed path is unexercised in this sandbox. Direct HTTPS to statsapi.mlb.com is blocked here, so the live board replays a stored, verbatim official capture. The network path itself (--today, --pk) is implemented but has not been run end to end against a live game from this environment.
  • June–September 2026 pool only — season-fatigue, weather and park effects on error rates are unmeasured, and generalising to other seasons is an extrapolation.
  • The scoring model ignores game context: score, outs, inning and leverage. A scorer at the end of a one-run game is not the same decision as one in the first inning of a blowout, and none of that is in the current feature set.
